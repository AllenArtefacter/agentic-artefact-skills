# Materials and Deliverables folder indexes

Maintain one native Google Doc named Materials inside the project's materials folder and one named Deliverables inside its deliverables folder. Respect actual folder names and IDs; do not create duplicate folders to match numbering. These are project-specific inventories, not generic READMEs. Reuse existing index IDs and exclude the index itself.

During initialize, create or reconcile both indexes after listing their authorized folders; record their IDs in the manifest. An empty folder gets a short empty-state sentence, not invented entries. List actual files and nested collections using native file chips where supported, with one short purpose statement, verified owner/source or TBD, and current version/review status where relevant. Include related task IDs and a Tasks link for deliverables; a draft does not establish acceptance. Use concise blocks for a small inventory and a native table for a larger inventory. Show the last reconciliation date. Keep templates and general instructions inside the skill.

During work, update the affected index after an authorized file creation, upload, rename, move, archival or substantive revision. Match entries by canonical file ID, not title. Preserve human notes. For nested folders, link the subfolder and index relevant files with their location; never traverse above the authorized project root. Clearly distinguish external references from files contained in the folder. Do not move files merely to make the index appear complete.

After publishing an output, add its canonical file chip to the matching Task's Deliverables cell and include the task ID/link in the Deliverables index. Where appropriate and authorized, include the task backlink in the output document as well. Preserve existing multi-output row merges and IDs; an output may support multiple tasks. Do not infer DONE from file existence. Materials entries may link related meetings/tasks when the relationship is known. If no task matches, record the output with task TBD rather than inventing or approving a task.

Keep task execution status in Tasks and output review/acceptance status in the Deliverables index; do not maintain competing registers. These are on-demand updates when the skill runs, not a background watcher. Verify links, folder placement, and changed entries after writing; report any partial update.

Apply the project-wide [native chip convention](smart-chips.md) to people, dates/times and supported file references.
