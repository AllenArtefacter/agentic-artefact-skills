# Native Google chip convention

For all future native Google project authoring and edits, use native chips for known people, dates/times and supported file references. This covers Project, STATUS, notes/briefs, indexes, task registers, reports and deliverables, not only metadata. Preserve existing chips when editing. Apply this to the requested content; do not rewrite all historical documents without authorization.

- **People:** resolve person chips from confirmed email addresses. Do not guess identity from a name or reuse the maintainer's account for coworkers. Unknown identity stays TBD. Chips do not grant access, assign work or authorize notifications.
- **Dates/times:** use native date chips where supported, preserving the actual date, time, timezone and tentative/confirmed meaning. Use date-and-time chip properties only when supported and known; otherwise retain precise time/timezone beside the date chip. Do not invent a time or replace unknown dates with today. Sheets date-formatted values are not automatically date chips; do not claim equivalence.
- **Files:** use native file/resource chips for verified supported Google files. Preserve useful task/tab/range destinations as a separate descriptive deep link when a chip cannot retain them. Folders and external web sources may use descriptive hyperlinks if that resource type cannot render as a chip. Do not invent a chip for an unsupported target.

Inspect the current host integration's schema first. Use supported native insertion and verify native element properties (Docs person/dateElement/richLink; Sheets chipRuns or the relevant native representation). UI is a fallback when supported and authorized. A literal @email, @date, styled label or ordinary hyperlink is not a native chip. If the app, file type or current tool cannot produce a requested chip, explicitly report the specific limitation and retain a usable value/link; never silently claim chip compliance. Do not require additional Google scopes merely for appearance.

Templates use explicit PERSON_CHIP, DATE_CHIP and FILE_CHIP placeholders. Local Markdown/JSON drafts can retain values or placeholders; resolve them to native chips on publication. Readback verifies identity/date/URL and preservation of surrounding text. This convention does not require altering original raw meeting files or rewriting quoted source evidence.
